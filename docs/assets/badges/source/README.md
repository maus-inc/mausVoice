# Badge sources

The SVGs in `../` are generated by `generate-badges.mjs`. They replace
hot-linked badge images with an equivalent local, versioned set, styled as
black capsules with a hairline border, a light inner top highlight, and a
soft drop shadow.

Text is converted to font outlines at generation time with opentype.js, so
the published SVGs have no font-loading dependency (GitHub does not load
remote fonts inside `<img>` SVGs, and renderer-default fonts would break
the design).

Icon badges are optically centered: `svg-path-bbox` measures each glyph's
actual outline bounds and the glyph is centered on those, not on its
24-unit viewBox.

## Badges

| File | Used in |
| --- | --- |
| `license.svg` | Root README header row |
| `macos.svg`, `windows.svg`, `linux.svg` | Root README header row and download section |
| `promo-prod.svg`, `promo-enterprise.svg` | `release/README.md` promotion links |

The badge set deliberately avoids arrow characters because the Geist Latin
builds do not contain them (e.g. the promotion badges read "prod from
main").

## Regenerating

```bash
cd docs/assets/badges/source
npm install          # opentype.js + svg-path-bbox (see package.json)
node generate-badges.mjs
```

## Typefaces

- `fonts/Geist-500.ttf` / `fonts/Geist-600.ttf` — Geist by Vercel, licensed
  under SIL OFL 1.1 (see `fonts/OFL-1.1.txt`, upstream:
  <https://github.com/vercel/geist-font>). Converted from the
  `@fontsource/geist` WOFF2 builds with fontTools (`font.flavor = None`)
  purely so opentype.js can outline them. No glyph outlines were modified.
- To render badges in Satoshi instead, point `FONT_MEDIUM`/`FONT_SEMIBOLD`
  in `generate-badges.mjs` at `marketing/assets/fonts/Satoshi-Medium.ttf`.

## Platform glyphs

`glyphs.json` holds the Apple, Windows, and Linux (Tux) path data copied
verbatim from this repository's own assets (`index.html` hero OS marks and
the Windows logo long embedded in the README as a data URI), so the badges
match the product site exactly.

## The CI badge

The CI badge is intentionally **not** generated here: it must show live
status, so it stays a remote shields.io workflow-status badge (Test
Desktop Unit on main), styled flat black-on-black to sit well next to the
house badges, and lives inline beside the `# mausVoice` title in the root
README. A fully house-styled live badge would need CI infrastructure that
regenerates a committed asset on every workflow run, which we deliberately
do not have.
