### 0.2 Hard rules that apply to every phase

1. **No Tailwind, no `cn()`, no standalone `motion` package.** The UI stack is
   **MUI v7.3.9** (`@mui/material`) + **framer-motion 12.38** (import from
   `framer-motion`, not `motion/react`). Adapt pasted shadcn/ReactBits code to
   `theme.ts` `styleOverrides` + `sx`, never copy Tailwind classes verbatim.
2. **Font:** the app font is **Satoshi** (embedded; `theme.ts:14` `uiFont`,
   native pill crates embed their own via `font.rs`). All new text must be
   Satoshi on both stacks.
3. **Colors:** use the MUI CSS-variable palette (`theme.vars.palette.*`:
   `level0/1/2/3`, `blue`, `text.primary/secondary`) and the native palette in
   `packages/rust_*_pill/src/constants.rs` — never hardcode hex in components.
   Light surfaces: `surfaces.light.*` (`styles/palette.ts:23-37`), dark:
   `surfaces.dark.*`.
4. **Preferences pattern** (verified end-to-end, must be followed exactly):
   SQL migration in `apps/desktop/src-tauri/src/db/migrations/` (next free
   numbers: **069, 070**) → `domain/preferences.rs` (serde camelCase +
   `#[serde(default = "...")]`) → `db/preferences_queries.rs` (INSERT column
   list ~L25, `excluded.*` update list ~L95, SELECT list ~L186, row mapping
   ~L295) → `packages/types/src/preferences.types.ts` → mapping in
   `apps/desktop/src/repos/preferences.repo.ts` (`fromLocalPreferences` ~L74,
   `toLocalPreferences` ~L120) → settings UI with **optimistic update +
   revert-on-error** through `setUserPreferences`.
5. **Pill consistency rule:** geometry/animation math shared by the three pill
   crates lives in `packages/rust_pill_shared/src/lib.rs`. Any new ring/radius
   constants or helpers go there; `rust_macos_pill`, `rust_windows_pill`,
   `rust_gtk_pill` must stay pixel-identical for the same input.
6. **IPC protocol:** pill messages are newline-delimited JSON over stdin
   (`InMessage` enums in each pill's `ipc.rs`), tagged `{"type": "...", ...}`
   snake_case. Any new message must be parsed defensively (the GTK reader at
   `ipc.rs:132-140` already skips malformed lines without panicking — keep that

7. **No signing/updater work** — see `docs/RELEASE.md` rules. Nothing in this
   plan touches `.github/workflows`; if anything ever does, mirror it into

## 2. Phase 1 — Native pill: ring animation, radius, font, stability

### User goal
- The long-press ring must look as pristine as the internal sine waveform
  ("nothing as pristine as the sine wavelengths inside the pill").
- The inflate animation must not make the pill look like a button: the corner
  radius must scale with the inflate so the capsule proportion is preserved.
- Pill font + style selector fully Satoshi.
- Better stability/CPU/memory behavior of the pill process itself.

### Verified current state
- Shared geometry: `packages/rust_pill_shared/src/lib.rs` provides
  `rounded_rectangle_perimeter()`, `path_distances()`,
  `DRAG_INFLATE_SCALE = 0.18`, `DRAG_INFLATE_STIFFNESS = 280.0`,
  `update_ring_alpha()`, `LONG_PRESS_RING_FADE = 0.5`.
- Ring constants (shared): `RING_SHIMMER_CYCLES = 2.0`, three-pass constants
  (`RING_GLOW_WIDTH=5.0/α0.15`, `RING_MID_WIDTH=3.0/α0.35`,
  `RING_CORE_WIDTH=1.2/α0.85`), `RING_EDGE_FADE = 30.0`.
- Per-crate constants: `EXPANDED_RADIUS: f64 = 16.0` (macOS
  `constants.rs:20`, Windows `constants.rs:20`, GTK same), `LONG_PRESS_RING_RADIUS
  = 22.0`, `LONG_PRESS_RING_STROKE = 2.5`, `LONG_PRESS_OUTLINE_COLOR =
  (0.92, 0.95, 1.0)`.
- **Ring renderer** (`draw_long_press_ring`): macOS `draw.rs:1319`, Windows
  `draw.rs:1185`, GTK `draw.rs:179`. Current approach: 3 overlapping stroke
  passes × **8 quantized alpha buckets** per pass; per-segment alpha =
  `master_alpha * pass_alpha * (0.55 + 0.45·sin(mid_dist·freq + wave_phase)) *
  edge_fade`, with `ALPHA_BUCKETS = 8` rounding segments into buckets and one
  `stroke()` per populated bucket. The bucket quantization + sub-path joins are
  the "clunky / rubbish" look the user describes.
- **Waveform renderer (the reference look)** (`draw_waveform`): macOS
  `draw.rs:170`, GTK `draw.rs:330`, Windows `draw.rs:161` — one **continuous
  polyline** per wave config, round cap/join, single `stroke()` per config.
- **Radius bug (verified):** `pill_radius(pill_w, pill_h)` (macOS `draw.rs:113`,
  Windows `draw.rs:109`, GTK same) returns
  `(pill_w.min(pill_h) * 0.5).min(EXPANDED_RADIUS)`. Idle pill height = 32 →
  radius 16 = capsule. During drag-inflate, height = 32 × (1 + inflate·0.18) →
  e.g. 37.8px at full inflate → a true capsule needs r ≈ 18.9, but the clamp
  pins r at 16 → corners shrink *relative to the pill* → "looks like a button".
- **Font:** GTK `draw_flash_message` (`draw.rs:641`, `:650`) still uses Pango
  `FontDescription::from_string("sans bold 12")` / `"sans bold 11"` — the last
  non-Satoshi text in the pills. Everywhere else uses
  `cr.select_font_face("Satoshi", ...)` (GTK `draw.rs:475,544,596,1034,1064,
  1098,1111,1140,1169,1211`).
- **Stability:** per-frame code allocates `Vec`s in the ring path (segments
  vec) and waveform (rebuilt point lists) every frame; the three tick loops
  (macOS `app.rs`, GTK/Windows `pill.rs` — Windows tick at `pill.rs:539`) run
  springs; malformed IPC is tolerated in GTK (reader loop skips bad lines) —
  verify the same for macOS/Windows readers.

### Implementation steps

#### 1.1 Redesign the long-press ring (all 3 crates + shared crate)
> **User decision (Q4): the 2-pass dash-shimmer design is approved.**

Replace the 3-pass × 8-bucket renderer with the approved **two-pass,
dash-shimmer** renderer that reuses the exact perimeter geometry (unchanged
shared math):

- **Pass A (base outline):** the filled perimeter (progress-clipped) as ONE
  sub-path, single `stroke()`, constant soft alpha (≈0.30), width ~2.5.
- **Pass B (traveling shimmer):** the same path stroked with a **dash pattern**
  (e.g. dash cycle = perimeter / `RING_SHIMMER_CYCLES`, pattern ≈ `[40% on,
  60% off]`), brighter alpha (≈0.8), dash offset driven by `state.wave_phase`
  so the shimmer travels along the ring in sync with the internal waveform —
  exactly like the sine waves "bleeding through to the border". 2 stroke calls
  total, zero bucketing artifacts, cheap.
- Leading-edge fade stays: clip pass A/B to the progress length (existing
  `filled_len` segment-split logic) and add a short constant-alpha ramp near
  the head (≈12 segments with smoothly interpolated alpha) so the progress head
  doesn't pop.
- **Backend support check (do this first):** Cairo (`GTK`) has `set_dash`;
  macOS `gfx.rs` wrapper (cairo-based) needs a `set_dash` pass-through; Windows
  `gfx.rs` (Direct2D) needs an `ID2D1StrokeStyle` dash style added to the
  wrapper. This is the approved design; if a backend truly cannot do dashes,
  the interim fallback is **Pass A + head-ramp polyline with per-segment smooth
  (non-quantized) alpha interpolation** — the key regressions to avoid are the
  8-bucket quantization and the multi-pass overlap.
- Move the new constants (`RING_BASE_ALPHA`, `RING_SHIMMER_ALPHA`,
  `RING_DASH_CYCLE`, head-ramp length) and the
  `ring_alpha_at(dist, total_len, filled_len, wave_phase) -> f64` helper into
  `rust_pill_shared` with unit tests (monotonic fade near head, period ==
  `RING_SHIMMER_CYCLES`, returns 0 beyond `filled_len`).
- Keep `update_ring_alpha()` / hold-pinning semantics unchanged.

#### 1.2 Inflate-aware corner radius (all 3 crates)
> **User decision (Q5):** clarified in plain language below and recorded as an
> assumption — only the **long-press drag-inflate state** changes; the pill's
> idle and expanded (assistant/typing) look stays exactly as it is today.
>
> **Plain-language explanation of what this fixes:** right now, when you
> long-press and drag, the pill grows ~18% bigger, but the rounded corners
> stay the same size as before. A big pill with small corners reads as a
> "button" (or a rounded rectangle) instead of a pill. The fix makes the
> corners grow at the same rate as the pill itself, so the shape stays a true
> pill/capsule at every moment of the drag animation. The idle pill and the
> expanded assistant view are not affected — their corner radius stays 16px
> exactly as it is now.

- Change `pill_radius(pill_w, pill_h)` → `pill_radius(pill_w, pill_h, inflate)`
  and compute:

  ```
  base_cap  = EXPANDED_RADIUS                        // 16.0 (unchanged look when idle)
  scale     = 1.0 + inflate * DRAG_INFLATE_SCALE     // inflate = current smoothed spring value
  cap       = base_cap * scale                       // grows with the pill
  radius    = (pill_w.min(pill_h) * 0.5).min(cap)
  ```

- This preserves the **idle and expanded (assistant/typing) look exactly**
  (inflate = 0 → cap = 16), and makes corners true semicircles at every point
  of the drag-inflate spring (at full inflate: cap = 18.88 = half-height).
- Update all call sites (macOS `draw.rs:124,179,495,1194`; Windows
  `draw.rs:120,170,204,233,482,1042`; GTK equivalents) to pass the live inflate
  from `state.inflate` (or the smoothed `inflate_t` the spring already
  produces — reuse whatever the drag-inflate spring writes).
- Scale `LONG_PRESS_RING_RADIUS`/`LONG_PRESS_RING_STROKE` with the same
  `scale` factor so the ring keeps its optical distance from the growing pill.
- Add unit tests in `rust_pill_shared` (or per-crate `draw.rs` test modules):
  idle radius == 16; full-inflate radius == half of the scaled height;
  radius-to-height ratio constant across the spring range.

#### 1.3 Satoshi everywhere in the pills
- GTK `draw_flash_message()`: replace `pango::FontDescription::from_string
  ("sans bold 12"/"sans bold 11")` with the embedded Satoshi family
  (`cr.select_font_face("Satoshi", ...)` + weight, matching `draw.rs:475`).
- Audit the **style selector** rendering (the "Style: …" chips in the expanded
  view) in all three crates and every other text call site for non-Satoshi
  fallbacks; the embedded `font.rs` loaders (macOS 95 lines / Windows 76 lines /
  GTK 47 lines) are already Satoshi — verify each draw site actually uses the
  loaded face rather than a system face.

#### 1.4 Pill stability under CPU/memory pressure
- Remove per-frame heap allocations in `draw_long_press_ring` (reuse a
  scratch buffer for segments across frames or restructure to the 2-pass
  renderer above, which needs no per-frame Vec) and in `draw_waveform`
  (precompute x-position/phase tables per size; only amplitude/alpha change
  per frame).
- Tick loops: verify each platform's animation driver stops scheduling work
  when idle (no drag, no springs above threshold, phase idle, alpha ≤ 0):
  macOS `app.rs` (spring tick + long-press tick), GTK `pill.rs:539` `tick`,
  Windows `pill.rs:539` `tick`. Add early-outs.
- IPC hardening: confirm all three readers ignore malformed/oversized lines
  without panic or unbounded buffering (GTK already does; mirror in
  macOS/Windows). Rate-limit the `eprintln!` bad-message logging.
- Add `cargo clippy` to the pill crates' local check loop; run
  `cargo test -p rust_pill_shared` + per-crate `cargo check` on all three.

### Acceptance criteria
- Ring during active dictation visually matches the internal waveform quality;
  no visible bucket steps or pass-overlap fringes on 1× and HiDPI displays.
- Ring shimmer travels in sync with the waveform phase on all three OSes.
- Full drag-inflate: pill is a perfect capsule (radius = half height), no
  "button" look; idle and expanded views are pixel-identical to before.
- Flash message and style selector render Satoshi on all platforms.
- `cargo test` green in `rust_pill_shared` and pill crates; no per-frame
  allocations in the hot draw paths (spot-check with a profiler or by code
  review).

## 3. Phase 2 — "Reset Pill Position" monitor strategy preference

### User goal
Tray → Reset Pill Position should reset to the bottom of **either the monitor
the pill is currently on, or the monitor under the mouse cursor** — a user
setting, because multi-monitor setups differ.

### Verified current state
- Preference flow: migrations up to `068_app_target_insertion_method.sql`;
  `domain/preferences.rs` (camelCase serde, `#[serde(default)]` fields);
  `db/preferences_queries.rs` (INSERT ~L25, excluded-update ~L95, SELECT ~L186,
  row map ~L295); `packages/types/src/preferences.types.ts` (`UserPreferences`,
  `dictationPillVisibility` union at L33); `repos/preferences.repo.ts`
  (`LocalUserPreferences` L18, `fromLocalPreferences` L74, `toLocalPreferences`
  L120).
- Command: `reset_pill_position` at `commands.rs:1979` →
  `platform::overlay::notify_reset_position(&app)`.
- Rust side: `pill_process.rs:154` sends hardcoded `{"type":"reset_position"}`;
  macOS `platform/macos/overlay.rs:101` sends `InMessage::ResetPosition`;
  Linux/Windows overlays delegate to `pill_process` (`overlay.rs:46` both).
- Pill handlers: macOS `app.rs:441`, Windows `pill.rs:524`, GTK `pill.rs:516`
  clear `has_saved_position` + mark dirty (and send `PositionChanged`).
- Reposition logic (verified): macOS `reposition_window` (`app.rs:986`) and
  Windows `reposition_to_cursor_monitor` (`pill.rs:1016`) anchor on the cursor
  **only while dragging or on first placement**; otherwise they anchor on the
  saved position / the monitor the pill already lives on (comments explain this
  deliberately fixed a "pinned pill hops monitors" bug). GTK: X11 re-home loop
  (`pill.rs:645-690` via `monitor_at_point`) + `x11.rs` helpers; Wayland
  LayerShell path separate.
- Settings UI for pill behavior lives in
  `components/settings/MoreSettingsDialog.tsx` (pill visibility control at
  ~L289).

### Implementation steps

#### 2.1 Data layer (pattern per §0.2.4)
- Migration `069_pill_reset_monitor_strategy.sql`:
  `ALTER TABLE user_preferences ADD COLUMN pill_reset_monitor_strategy TEXT NOT NULL DEFAULT 'current';`
- `domain/preferences.rs`: add
  `#[serde(default = "default_pill_reset_monitor_strategy")] pub pill_reset_monitor_strategy: String`
  + `fn default_pill_reset_monitor_strategy() -> String { "current".into() }`.
- `preferences_queries.rs`: add the column to the four spots listed in §0.2.4.
- `packages/types/src/preferences.types.ts`:
  `export type PillResetMonitorStrategy = "current" | "cursor";` + field on
  `UserPreferences` (default `"current"`).
- `preferences.repo.ts`: map in both directions.

#### 2.2 Thread the strategy into the pill IPC
- `pill_process.rs`: `notify_reset_position(app, strategy: &str)` →
  `{"type":"reset_position","strategy":"<strategy>"}`; `notify_reset_position`
  becomes fallible (`Result<(), String>` — `PillProcess::send` hardening comes
  in Phase 8.3; reuse it here).
- `commands.rs:1979`: fetch `fetch_user_preferences`, resolve
  `pill_reset_monitor_strategy` (default `"current"`), pass to overlay.
- `InMessage::ResetPosition` in all three pill `ipc.rs` files becomes
  `ResetPosition { strategy: ResetStrategy }` with a new
  `enum ResetStrategy { Current, Cursor }` (serde `snake_case`) and
  `#[serde(default)]` on the field so a missing/older payload degrades to
  `current`.
- Pill handlers: instead of just clearing the saved position, set a
  `reset_strategy` cell (`Cell<ResetStrategy>`) consumed by the reposition
  paths:
  - **`current`** (default): re-home bottom-centre of the monitor the pill
    currently lives on (existing anchor logic, just without the saved
    position).
  - **`cursor`**: force the reposition anchor to the cursor's monitor
    (`mouse_location()` macOS / `GetCursorPos` + `MonitorFromPoint` Windows /
    `monitor_at_point` GTK), i.e. temporarily apply the "first placement"
    branch, then clear the flag once placed.
- Preserve the existing guardrails (no chasing the cursor on later ticks;
  fall back to primary monitor if the cursor's monitor is gone — GTK already
  does this in `x11.rs:198-205`, mirror on macOS/Windows).

#### 2.3 Settings UI
- `MoreSettingsDialog.tsx`: next to pill visibility (~L289) add a
  `SegmentedControl<PillResetMonitorStrategy>` ("Current monitor" /
  "Cursor monitor") using the existing optimistic-update + revert-on-error
  pattern already used by that dialog (state update first, `setUserPreferences`
  persist, revert + error snackbar on failure).
- After the value is persisted, tray Reset uses the new strategy on next click
  (no restart needed).

### Acceptance criteria
- Fresh install defaults to `current` (no behavior change).
- With two monitors: strategy `current` re-centers on the pill's own monitor;
  strategy `cursor` re-centers on the monitor under the mouse, from the tray
  menu and from any reset call.
- Setting persists across restarts; migration upgrades existing profiles
  without data loss.
- `cargo check` for the Tauri app; `pnpm check-types` green.

### 3.2 Implementation steps

1. **Migration `071_remove_cloud_modes.sql`:**
   ```sql
   UPDATE user_preferences SET transcription_mode = 'local' WHERE transcription_mode = 'cloud';
   UPDATE user_preferences SET post_processing_mode = 'none' WHERE post_processing_mode = 'cloud';
   UPDATE user_preferences SET agent_mode = 'none' WHERE agent_mode = 'cloud';
   ```
   Rationale: transcription falls back to the always-available local engine
   (the settings UI will guide the model choice); post-processing and agent
   mode fall back to off/verbatim — the honest post-cloud state, with no
   surprise API spend. NULLs need no migration: after §3.2.3 the fallback
   chain resolves them to `local` / `none` / `none`.
2. **Types:** drop `"cloud"` from the three unions in `common.types.ts`.
   `PostProcessingMode` becomes `"none" | "api"` and `AgentMode` becomes
   `"none" | "api" | "openclaw"`.
3. **`user.utils.ts`:** delete `CloudTranscriptionPrefs`,
   `getHasCloudAccess`, and all cloud branches in `getTranscriptionPrefs` /
   post-processing prefs; change `resolveMode` to
   `mode ?? fallback` (the fallbacks are already `"local"` / `"none"` /
   `"none"` — behavior for non-cloud users is unchanged). Remove `isCloud`
   and the word-limit cloud gating; simplify `personal-use.utils.ts` (no
   cloud counting) and its tests.
4. **Repos/sessions/strategies:** delete cloud branches in

## 7. Phase 6 — Fix light mode (verified root cause)

### User goal
Light mode must actually work. It is currently "hardcoded" — the UI stays dark
even after switching.

### Verified root causes (two bugs, both in the bootstrap path)
1. **Inline style wins forever.** `apps/desktop/index.html` pre-hydration script
   sets `document.body.style.backgroundColor = "#0c0c0d"` (dark) or
   `"#f5f2ed"`. An inline style beats every stylesheet rule, including
   `MuiCssBaseline`'s `body { backgroundColor: themeParam.vars.palette.level0
   }` (`theme.ts:154-166`). So the runtime theme can never repaint the body —
   switching to light flips all themed components but the page canvas behind
   them stays dark (`#0c0c0d`), i.e. light mode looks broken/hardcoded.
2. **Storage-key mismatch.** The script reads `localStorage.getItem("mode")`,
   but `ThemeProvider` (`main.tsx:122`) passes no storage key, so MUI
   `useColorScheme` uses its default key (`mui-mode`). The pre-hydration
   resolution therefore always falls back to `system`, producing a
   wrong-color flash at launch and meaning the script and the app disagree
   about the persisted mode.

### Implementation steps
1. **index.html:** remove the inline-style assignment. Instead:
   - Keep the no-JS CSS fallback (`body { background-color: #0c0c0d }` +
     `@media (prefers-color-scheme: light) { ... #f5f2ed }`).
   - Add boot classes:
     `body.boot-theme-dark { background-color: #0c0c0d !important; }` and
     `body.boot-theme-light { background-color: #f5f2ed !important; }`.
   - Script: compute the resolved mode (same logic) and set
     `document.body.classList.add("boot-theme-light" | "boot-theme-dark")`
     instead of the inline style.
2. **Mount cleanup:** in `main.tsx` (or `AppWrapper`) first effect:
   `document.body.classList.remove("boot-theme-dark", "boot-theme-light")`.
   From then on `MuiCssBaseline` owns the body background via
   `theme.vars.palette.level0`, including its existing 220ms transition — the
   pre-hydration paint only ever covers the gap before React mounts.
3. **Align storage keys:** set `colorSchemeStorageKey="mode"` (and
   `modeStorageKey="mode"` if MUI v7 still splits the props) on the
   `ThemeProvider` in `main.tsx:122` so MUI reads/writes the same `"mode"` key
   the bootstrap script reads. (Verify against the installed MUI 7.3.9 types;
   choosing `"mode"` preserves any values users already persisted.)
4. **Verify the toggle path:** `components/root/ThemeModeToggle.tsx` (uses
   `useColorScheme()`, `setMode`) should now visibly flip the entire canvas;
   test all three modes (light / dark / system + OS switch mid-run).
5. Regression check: search for any other `document.body.style` /
   `backgroundColor` hardcoding (`grep -rn "body.style"`), and confirm
   `color-scheme: light dark` in `index.html` doesn't need updating.

### Acceptance criteria
- Switching light ⇄ dark repaints the **body** immediately (no stuck dark
  canvas); launching in persisted light mode shows no dark flash.
- `localStorage "mode"` and MUI agree (single key).
- No white flash in dark mode on cold start.

## 8. Phase 7 — Local transcription reliability + spec-based model advice

### User goal
- Local models must not hard-fail with the
  `…request for url (http://127.0.0.1:55300/v1/transcriptions/sessions/ed5a…)`
  error on low-spec devices.
- Solidify usability; **recommend (or discourage) models based on the device's
  actual specs** instead of letting users pick a model that can't run.

### Verified current state
- Frontend sidecar: `sidecars/base.sidecar.ts` (288 lines) — `markActivity()`
  (L103) resets an idle timer; `local-transcription.sidecar.ts` uses
  `SIDECAR_IDLE_DISPOSE_MS = 60_000` (L108) and calls `markActivity()` only
  **after a successful `requestJson`** (L600). Streaming chunk uploads go
  through `requestJson` (`createStreamingSession` L275+, chunk queue ~L330),
  so activity is marked per chunk — but any gap > 60s (long pause, mic
  silence, user holds the pill without speaking) lets the **idle-dispose kill
  the sidecar process mid-session**.
- Failure chain (matches the quoted error): sidecar killed → next
  chunk/finalize gets a transport error ("…g request for url
  (http://127.0.0.1:55300/v1/transcriptions/sessions/ed5a…)") →
  `requestJson` transport path calls `resetRuntime()` → respawned process has
  no memory of the session → Rust sidecar answers 404
  `session_not_found` (`packages/rust_transcription/src/api.rs:308` chunk append,
  `:330` finalize).
- Error handling today: `isModelMissingError` (`local-transcription.sidecar.ts`
  ~L570) only recognizes 404 + `model_not_downloaded`; there is **no**
  `session_not_found` recognition. `sessions/local-transcription-session.ts`
  (197 lines) already has `finalizeWithBatchFallback(audio, warnings)` (L150)
  and uses it on model-missing (L98/L127) — the exact recovery path to reuse.
- Rust sidecar session TTL: `streaming_sessions.rs` `SESSION_IDLE_TTL = 10min`
  with per-chunk activity touch (L104) — a secondary, not primary, trigger.
- Specs: GPU enumeration exists (`system/gpu.rs`,
  `apps/desktop/src/hooks/gpu.hooks.ts`, command `list_gpus` at
  `commands.rs:491`). **No RAM/CPU query exists**; `sysinfo` is not in
  `apps/desktop/src-tauri/Cargo.toml`. Model sizes in UI
  (`AITranscriptionConfiguration.tsx`): base 148MB, small 488MB, medium
  1.53GB, turbo 1.6GB, large 3.1GB, hindi 595MB (+ tiny at the top of the
  list).

### Implementation steps

#### 7.1 Kill the `session_not_found` failure
1. `base.sidecar.ts`: add an **activity lease** API next to `markActivity`:
   `beginActivityLease(): () => void` — while any lease is held, the idle
   timer is never scheduled (or is canceled). Keep `markActivity` for
   request-driven refresh.
2. `local-transcription.sidecar.ts`: acquire a lease in
   `createStreamingSession()` and release it in `releaseSession()` and in
   every finalize/error exit path (`finally`). Result: an open streaming
   session pins the sidecar process regardless of chunk cadence.
3. Add `isSessionNotFoundError(error)`: `SidecarRequestError` with
   `status === 404 && error.code === "session_not_found"`.
4. `local-transcription-session.ts` `finalize`: on `session_not_found` **or**
   transport error during chunk/finalize, log a warning and return

   model-missing). Do not surface a hard failure.
5. Logging for future diagnosis: log sidecar PID + session id at

6. Optional hardening: raise `SESSION_IDLE_TTL` to 30min in

#### 7.2 System-spec detection + recommendations
1. **Rust:** add `sysinfo` to `apps/desktop/src-tauri/Cargo.toml`; new

2. **TS:** hook `system-capabilities.hooks.ts` (mirror `gpu.hooks.ts`);

3. **Recommendation matrix** (RAM-driven, GPU relaxes by one tier):

## 9. Phase 8 — Dictation "processing" race, watchdog, deterministic cleanup

### User goal
After the pill inserts transcribed text, it must **never stay stuck in the
processing state** — the stuck state preceded a memory-leak-style system crash
on the user's machine. Also: better error recovery + stability of the main
pill.

### Verified current state (root causes)
- `components/root/DictationSideEffects.tsx` (1014 lines):
  - `stopRecordingRaw`: phase `loading` set at ~L327 (inside `Promise.all`
    with `stop_recording`); then `finalize` (~L379), then
    `strategy.handleTranscript` (~L404+).
  - **Idle is only restored by:** (a) the agent-only branch
    `if (activeRecordingMode === "agent") strategy.setPhase("idle")` (~L406),
    or (b) `abortRecording` (~L271) invoked from `stopRecording` **only when
    `res.shouldContinue === false`** (~L480). `DictationStrategy` returns
    `shouldContinue: false` (dictation.strategy.ts L155/L237) while
    `AgentStrategy` returns `true` (agent.strategy.ts L98/L113) — the
    semantics are per-strategy and unreliable as a phase-reset signal.
  - Any throw/hang **between** `finalize` and the return — most importantly
    `handleFinalStreamedTranscript` awaiting `this.pasteQueue`
    (`dictation.strategy.ts:147`), where the queue chains
    `routeTranscriptOutput` per interim segment — leaves the pill at `loading`
    forever. This matches the user's exact symptom: text was pasted, pill kept
    spinning.
  - `abortRecording` calls `sessionRef.current?.cleanup()` /
    `strategyRef.current?.cleanup()` **without await and without try/catch**
    (L285-286) and issues `invoke("set_phase", { phase: "idle" })` without
    awaiting; on a hung/memory-pressured machine these fire-and-forget calls
    are exactly what gets lost, and cleanup never runs → audio buffers held →
    leak.
- `DictationStrategy.cleanup()` is a no-op (`dictation.strategy.ts:257`) —
  `pasteQueue` and streaming state survive an abort, so a stale queued paste
  can still resolve/type after the session is "gone".
- IPC reliability: `pill_process.rs` `PillProcess::send` (L16) locks stdin,
  writes, and **only logs** on failure (`log::warn!`); `notify_phase` is
  infallible; `commands.rs:1677` `set_phase` therefore can't tell the frontend
  the pill never heard it. No sequence numbers, no retry, no liveness check.

### Implementation steps

#### 8.1 Atomic phase pairing (DictationSideEffects.tsx)
- Restructure `stopRecordingRaw` so `setPhase("loading")` (entry) and
  `setPhase("idle")` are paired in a **`try/finally`** around the whole
  finalize→post-process→route chain. For agent mode, keep the existing
  explicit idle-before-agent-continuation, but make the `finally` the single
  safety net that always runs (idempotent; sending `idle` twice is harmless).
- Remove `shouldContinue` as the phase-reset trigger: it keeps its meaning for
  "keep recording/agent alive", but phase convergence no longer depends on it.
- Both paths (dictation + agent) must converge to `idle` on success **and** on
  every error path (each early `return { shouldContinue:false }` at
  ~L356/L388/L400 gets swept up by `finally`).

#### 8.2 Watchdog timeouts
- Add a small `withTimeout(promise, ms, label)` helper and wrap the three
  awaits: `finalize` (90s — CPU transcription of long audio is slow),
  `handleTranscript` (60s — LLM post-processing), and the internal paste
  routing leg (30s — see §8.4 audit). Constants at the top of the file,
  documented.
- On timeout: log + `abortRecording` with a user toast ("Processing timed
  out — please try again") + guaranteed phase idle via §8.1's `finally`.

#### 8.3 Reliable phase IPC (Rust)
- `pill_process.rs`: `PillProcess::send` → return `Result<(), String>`;
  add **one immediate retry** on write failure; add a monotonic **sequence
  number** to `notify_phase` payloads (`{"type":"phase","phase":"idle","seq":N}`)
  and keep a `last_seq` guard in each pill's `InMessage::Phase` handler so a
  stale/duplicated message can't regress the rendered phase (belt-and-braces;
  the pipe is ordered, the real risk is dropped writes — the retry + error
  surfacing is the primary fix).
- Make `notify_phase` fallible and propagate the error up through
  `set_phase` (`commands.rs:1677`) so the frontend can retry once and/or toast.
- Cheap liveness check: `try_wait()` on the child in `send` — if the pill
  process is dead, return a distinct error so the frontend knows the overlay
  needs respawning instead of silently staying stale.
- Pill side: `InMessage::Phase { phase, seq }` with `#[serde(default)]` on
  `seq` (backward compatible), skip if `seq < last_seq`.

#### 8.4 Deterministic cleanup
- `abortRecording`: `await` + `try/catch` both cleanups; make
  `invoke("set_phase", { phase: "idle" })` awaited with `.catch` + single
  retry (reuse §8.3 error path); clear `recordingWarningTimerRef`,
  `recordingAutoStopTimerRef`, `cancelPromptTimerRef` in a `finally` shared
  with the stop path (they are cleared at L230-241 today, but only on the
  happy path).
- `DictationStrategy.cleanup()`: reset `pasteQueue = Promise.resolve()`,
  `streamedSegmentCount = 0`, `streamedProcessedText = ""`,
  `currentAppId = null` (guarded — a queued paste that already started cannot
  be un-started, so also audit `utils/output-routing.utils.ts` for unbounded
  retry loops and add a bounded retry/abort-flag so pastes stop promptly once
  cleanup runs).
- Audit `sessionRef` finalize paths for retained audio: after
  finalize/fallback, drop references to the PCM payload (they live in the
  `StopRecordingResponse` closure; ensure no global capture survives).

#### 8.5 Phase reconciliation heartbeat (safety net)
- Add a low-frequency (every 5s, only while `recordingState === "idle"` &&
  last-sent phase ≠ idle) re-send of `set_phase idle` in
  `RootSideEffects.ts`/`DictationSideEffects.tsx` — self-heals any remaining
  desync from dropped IPC without visible cost.

### Acceptance criteria
- 50 consecutive dictations on a loaded machine: pill never sticks in
  processing; paste always followed by idle within the watchdog bounds.
- Killing the pill process mid-dictation: app detects, recovers phase on next
  heartbeat, no crash.
- Timers/cleanup verified via logs (no lingering timers, cleanup called exactly
  once per session).
- Rapid stop/start spam does not interleave phases (seq guard).
- `pnpm lint/check-types/test` + `cargo check` green.

## 10. Cross-cutting: performance & responsiveness under congested CPU/memory

These apply across phases; do them once, early (they feed Phases 1 and 8):

1. **Pill render loops:** eliminate per-frame allocations (ring segments,
   waveform point lists); precompute static geometry per pill size; ensure
   tick loops no-op when idle (Phase 1.4).
2. **Frontend store:** audit `useAppStore(selector)` selectors in the hot
   paths (`DictationSideEffects`, `AudioDialog`, `SettingsPage`) for
   object/array identities created per call → re-render storms. Cache with
   `useShallow`/primitive selectors where needed.
3. **Audio memory:** confirm recording buffers are dropped after finalize or
   fallback (Phase 8.4); confirm `stop_recording` always releases the native
   capture buffer even on error paths.
4. **IPC backpressure:** the pill stdin pipe must not grow unbounded — if
   `levels` messages are emitted per audio frame under load, coalesce/throttle
   them at the Rust `notify_audio_levels` sender (drop intermediate frames
   when the pipe write fails) rather than queuing forever.
5. **Error recovery:** `ErrorBoundary` (root) must reset dictation state on a
   UI crash (invoke `set_phase idle` in the boundary's fallback effect) so a
   React crash can't leave the pill stuck.
