Use the [mausVoice GitHub issue tracker](https://github.com/maus-inc/mausVoice/issues) for normal bugs, documentation corrections, and feature proposals.

A bug report should identify version, platform, installation type, mode/provider without credentials, target application, expected/actual behavior, and a minimal reproduction. State which pipeline stage succeeded—for example, whether correct raw text reached History or clipboard.

A feature request should describe the user problem before prescribing an implementation. Note platform constraints, privacy implications, and whether the request concerns transcription, rewriting, insertion, Assistant behavior, or the native pill.

Do not use a public issue for active secrets, private transcripts, exploit details requiring coordinated handling, or conduct incidents. Use private maintainer contact for those cases.
