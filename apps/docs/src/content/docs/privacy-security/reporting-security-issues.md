---
title: "Report a security issue"
description: "Share a reproducible security report without leaking credentials or user data."
sidebar:
  order: 5
---

Do not post active API keys, private transcripts, raw databases, or unreviewed diagnostics in a public issue. Revoke any credential that appeared in a report or screenshot.

For an ordinary non-sensitive bug, use the [GitHub issue tracker](https://github.com/maus-inc/mausVoice/issues) with the release version, platform, configuration mode, and minimal reproduction. For sensitive reports, contact the maintainer privately using the email path in the repository's Code of Conduct or the project's published security guidance.

A strong report states the affected boundary, expected result, actual result, and exact version. Include a minimal sanitized proof, whether a default configuration is affected, and any mitigation already tested. Separate provider-account behavior from mausVoice behavior where possible.

Give maintainers time to investigate before public disclosure. Do not test against accounts, devices, or services you do not own or have permission to assess.
