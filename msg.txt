fix(voice-ai): clear the gitleaks range finding on the redaction fixture

Two scans run in secret-scan.yml and they behave differently. The `--no-git`
one reads the working tree, and the range one reads every commit in the pull
request's range, so a literal that a later commit removed still comes back from
history.

Both had to be dealt with. The tree scan was still failing on
`["an api key assignment", "api_key=abc123def", "api_key"]`, which arrived with
#233 and is the last contiguous `label=value` literal left in the tree. It is
split at the label boundary now, like the ones beside it.

The range scan was failing on the line the previous commit had already split,
in `f4a3d740`, which is still inside the range. Splitting the tree cannot clear
that, so the finding is baselined by fingerprint in `.gitleaksignore`, with the
reason written next to it. That file is a fingerprint baseline by design and
says so itself; the alternative was rewriting published history on a staging
branch for a fixture.

`scripts/ci/check-gitleaks-config.mjs` passes, so the baseline is well-formed.

CodeAnt's 5 remaining bugs are all on `f4a3d740` and all fixed since: the
sherpa-onnx android link mode, the volume dim race, the empty authoritative
transcript, the replay filter, and the preview's pairing payload.
