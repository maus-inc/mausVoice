sherpa-onnx prebuilt payload
============================

Why this file is here
---------------------
`patches/sherpa-onnx-sys-1.13.5/build.rs` downloads a prebuilt archive from GitHub
Releases at build time when no local copy is configured:

    const RELEASE_BASE_URL: &str = "https://github.com/k2-fsa/sherpa-onnx/releases/download";
    url = format!("{RELEASE_BASE_URL}/v{version}/{archive_name}")   // version = CARGO_PKG_VERSION = 1.13.5

A GitHub Release asset download is a 302 redirect to `objects.githubusercontent.com`,
which a network-restricted sandbox cannot reach. Shipping the archive here lets the
consumer hand it to `build.rs` through `SHERPA_ONNX_ARCHIVE_DIR`, which keeps the
pinned digest check live.

Vendored archive
----------------
File    : sherpa-onnx-v1.13.5-linux-x64-static-lib.tar.bz2
Source  : https://github.com/k2-fsa/sherpa-onnx/releases/download/v1.13.5/sherpa-onnx-v1.13.5-linux-x64-static-lib.tar.bz2
Size    : 22394054 bytes
sha256  : 2ade8b7c62de66b9cf2e32bd7dbe077addaa4b18f422b49dc1bf3a1a0b1f762e

That digest is the value `build.rs` pins in `ARCHIVE_SHA256_DIGESTS` for
`sherpa-onnx-v1.13.5-linux-x64-static-lib.tar.bz2`, and the downloaded file was
verified against it. It is the upstream published artifact, unmodified.

Why the static linux-x64 archive
--------------------------------
`archive_name()` selects `sherpa-onnx-v{version}-linux-x64-static-lib.tar.bz2` for
`(LinkMode::Static, "linux", "x86_64")`, which is what
`packages/rust_transcription/Cargo.toml` requests on non-Windows and non-Android
(`features = ["static"]`).

Libraries `build.rs` links statically (SHERPA_ONNX_STATIC_LIBS)
--------------------------------------------------------------
sherpa-onnx-c-api, sherpa-onnx-core, kaldi-decoder-core,
sherpa-onnx-kaldifst-core, sherpa-onnx-fstfar, sherpa-onnx-fst,
kaldi-native-fbank-core, kissfft-float, piper_phonemize, espeak-ng, ucd,
onnxruntime, ssentencepiece_core

On Linux it additionally links `stdc++` and `m` as dylibs. A consumer debugging an
undefined symbol should look in this list first.

Consumer escape hatches, in the order `build.rs` evaluates them
--------------------------------------------------------------
1. `DOCS_RS=1` skips downloading and linking. Do NOT use: it changes what gets
   linked and the resulting binary is not the one CI tests.
2. `SHERPA_ONNX_LIB_DIR=<dir>` is used directly as the lib directory. This bypasses
   the archive and the digest check entirely. `build.rs` errors if the directory does
   not exist.
3. `SHERPA_ONNX_ARCHIVE_DIR=<dir>` makes `build.rs` copy
   `<dir>/sherpa-onnx-v1.13.5-linux-x64-static-lib.tar.bz2` into its cache and verify
   the pinned digest. This is the documented path in FETCH.md, because it keeps the
   digest check live. It errors with
   `SHERPA_ONNX_ARCHIVE_DIR does not contain expected archive: <path>` when the file
   name is not exactly right.

Cache layout `build.rs` maintains
---------------------------------
<CARGO_TARGET_DIR or .../target>/sherpa-onnx-prebuilt/
    sherpa-onnx-v1.13.5-linux-x64-static-lib.tar.bz2
    sherpa-onnx-v1.13.5-linux-x64-static-lib/lib/            <- what gets linked
    sherpa-onnx-v1.13.5-linux-x64-static-lib.extracted.sha256

`build.rs` re-verifies the extracted tree against the recorded digest and re-extracts
from the verified archive when it does not match. If a consumer pre-seeds the
extracted directory without the archive, `build.rs` discards it as unverifiable
("the archive it came from is missing") and tries to download. Pre-seed the archive,
or use `SHERPA_ONNX_ARCHIVE_DIR`.
